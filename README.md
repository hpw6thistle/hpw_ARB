# GitHub Pages 匿名互動展示 v1.9.0

展示版不需要 FastAPI、資料庫、登入帳密或外部服務。12 個館別名稱與數據均由程式重新產生，沒有使用上傳工作簿的金額、正式館名、員工資料或部署秘密；損益科目採通用科目名稱、代碼及彙總結構。

可體驗預算草稿、房晚／AHR／REV、提交唯讀、Excel 108 列範本下載／本機匯入、財務比較與獨立來源快照。畫面依需求暫時隱藏環境、試算與核定提示文案；此調整僅涉及呈現。

修改只保存在 sessionStorage 的專用展示鍵，不同步到別人或其他裝置；瀏覽器可能保留／還原分頁工作階段，請用帳號選單中的「重設資料」明確清除。請勿輸入真實資料。Excel 只在瀏覽器解析，不上傳；CSP 禁止 API／外部連線。

## v1.9.0 年度比較與主管操作架構

- 左上標題統一為「年度客房預算」。各館／聯訂的直式表不再顯示覆寫；REV 自動由 R/N × AHR 計算。財務調整仍可覆寫 REV 並精確回算 AHR。
- 導覽列新增「年度比較」，各館與聯訂只查看所屬來源，財務可比較授權範圍的同來源版本。手機將財務入口縮寫為「財務比較」，保留年度比較入口。
- 預設呈現全年與 12 個同月份，也可選全年度或單月；四項指標為可售房晚、R/N、含稅 REV、OCC，並列去年／今年／增減。
- 可指定今年版本及去年同來源版本；去年預設選最近已提交版本（沒有已提交才選最近草稿），目前編列版本優先作為今年選項。兩側明確標示草稿／已提交，更新資料保留選擇。
- 年度 OCC 使用全年房晚／全年可售，不平均月比率；OCC 差異以百分點呈現。沒有去年版本用破折號，不當成零；已編列零值維持 0。
- 此頁比較兩年度預算，不含去年實績。各館／聯訂沿用各年度目前房晚設定，財務版本沿用帶入時的房晚設定。
- 新增匿名生成的 2026 年各館及聯訂預算，供與 2027 年對照；舊分頁首次使用會補上這組資料，既有版本及修改不會覆寫。正式後端沒有新增假歷史資料，沒有資料時顯示缺資料。
- [ASCII 全站架構與角色流程](docs/SITEMAP.md)、[可編輯的 draw.io 兩頁圖](docs/annual-room-budget.drawio)。draw.io 檔可用 diagrams.net「檔案 → 從裝置開啟」。

建立財務調整草稿 → 調整房晚與房價 → 儲存並預覽報表 → 損益科目編列 → 檢查稅前／稅後損益 → 下載 Excel 或列印 PDF，確認後提交版本。提交即鎖定編列；主管核定仍是後續功能，不將提交視作核准。

## v1.8.0 財務報表與介面調整（位置以 v1.8.1 為準）

1. 開啟「財務比較」，選擇已提交來源，再建立財務調整草稿。
2. 調整房晚或房價後，按「儲存並預覽報表」。
3. 在「損益科目編列」依月份／分類輸入金額，再儲存；金額以未稅編列，支援三位小數。
4. 切換客房部損益、客房收入、收入差異、損益差異及通路明細；勾選「顯示全部 206 科目」檢視完整損益表。
5. 「下載 Excel（7 表）」包含完整 206 科目、年度客房收入、通路收入明細、收入調整差異、損益調整差異、通路調整明細與報表資訊。列印／另存 PDF 使用目前選取報表。

- 損益金額使用十進位三位小數；所得稅預設沿用原表（1 月正數稅前損益 × 20%，其他月輸入），可選每月 20% 或全部手動。
- 年度 ADR、OCC、RevPAR 及成本率依全年合計重新計算。客房未稅收入採逐月除以 1.05、四捨五入後加總，除稅尾差在報表列明。
- 財務版本建立時產生匿名人事、成本及費用，來源快照與初始損益基準獨立保存；調整不更動原始版本。舊分頁的財務版本會使用相同規則補上初始科目。
- 尚未儲存的收入或費用會先儲存成功，再輸出；已提交版本不可修改。費用輸入錯誤會阻擋匯出，並可還原變更。
- Excel 是產製時的數值快照，修改 Excel 不會回寫網站；超過 Excel 15 位有效數字時以文字保留精度。
- 不可售房晚的整個 12 個月區域採柔和紅色系，館別／年度／版本於導覽列右側壓成一行（手機位於第二行，仍保持同一列）。

## 本機建置與測試

需要 Node.js >=22.12（建議 24）。

```bash
cd frontend
npm ci
npm run build:demo
npm run preview:demo
```

輸出為 frontend/dist-demo/index.html、assets 與 .nojekyll。相對資產路徑支援 GitHub 專案子路徑。

```bash
# frontend 目錄；需要 Chromium
npm run test:demo
# 有系統 Chromium 時，可設定 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH
```

測試包括二十三項瀏覽器與財務運算測試，使用純靜態伺服器的 /hpw_ARB/ 子路徑。正常 production build 與原本後端工作流程仍可使用。

## 此儲存庫的分支用途

- pages-demo：僅匿名前端原始碼、展示測試與 Pages Actions，不包含正式後端、工作簿、DB、秘密或原始專案歷史。
- gh-pages：僅建置好的 index.html、assets、.nojekyll，可直接從分支發布。
- main：不因這次展示發布被替換或自動公開。

## 最少設定的發布方式

有儲存庫管理權限，且方案允許該儲存庫使用 Pages 時：

1. 開啟儲存庫 Settings → Pages。
2. Build and deployment → Source 選 Deploy from a branch。
3. Branch 選 gh-pages，資料夾選 /(root)，按 Save。
4. 等 GitHub 的 Pages build/deployment 完成，從設定頁的 Visit site 開啟。
5. 目前儲存庫的預期網址為 https://hpw6thistle.github.io/hpw_ARB/；在 GitHub 確認成功前，不將它當成已上線。

如果 GitHub Free 對目前私有儲存庫不提供 Pages，請另建只放匿名展示檔的公開儲存庫，例如 hpw-budget-demo；不要為此公開含正式資料的其他專案。

最簡單的網頁操作：解壓「GitHub_Pages_靜態網站_v1.9.0.zip」，將 index.html、整個 assets 資料夾與 .nojekyll 上傳到新公開庫的根目錄，提交至 main，再於 Pages 選 main / (root)。不要只上傳 ZIP，也不要多包一層資料夾。網址會是 https://你的帳號.github.io/新儲存庫名稱/。

## 可持續更新的 Actions 方式

使用匿名原始碼分支／原始碼 ZIP 時，可將 Pages 的 Source 改成 GitHub Actions；.github/workflows/pages-demo.yml 會在 main 或 pages-demo 的相關檔案更新時安裝、建置、執行展示測試，再部署。需要 GitHub Pages 已啟用及 github-pages 環境允許該發布分支；首次設定可能需要管理員操作。

configure-pages 的自動啟用功能需要額外的管理權限 token，不能假設一般 GITHUB_TOKEN 能替管理員開啟 Pages。因此此專案不要求將 PAT 或其他秘密放入展示版。

## 驗證與限制

- 本機已用 GitHub 專案子路徑驗證，不依賴 API／資料庫。
- 只有前端互動示範，不是多人共同編列、可信登入或正式財務核定系統。
- 實際 GitHub 發布狀態，以 Pages 設定頁、部署結果及公開網址實測為準；Git 推送成功不等於 Pages 已啟用。
